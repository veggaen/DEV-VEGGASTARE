# Messages preview — 26 September 2026

Status: **Live; scoped local, Preview and Live acceptance passed.** Production-safe runtime
`6190eb4`; integrated Preview runtime `9015bf0`. This is a scoped UI/read-state
release, not a declaration that all messaging or every route is production-ready.

## Changes

- Header Messages now works on phones as well as desktop. The existing Radix
  popover handles positioning, focus return and outside interaction; the panel
  stays within available viewport width/height with a separately scrolling list.
  Search, New chat, Close and Open full inbox have 44px targets. Theme tokens,
  reduced motion and visible keyboard focus replace independent colors/staggers.
- New chat opens the real `/conversations/new` form. Private-DM previews use
  participant details instead of treating string participant IDs as objects;
  sender prefixes and image-only previews use the actual API fields. Latest
  activity replaces creation-time ordering. No invented unread badge is shown.
- On-demand, bounded fetches replace the always-mounted timer and manual portal.
  Each account/navigation has isolated component state. Closing, signing out or
  switching accounts aborts pending work and ignores late responses. Nothing is
  stored in localStorage. Timeouts, malformed data and network errors show Retry;
  revoked access shows Sign in, never a misleading empty inbox.
- Search explicitly covers recent chats only. Existing API authorization and
  pagination semantics remain unchanged. No mutation API, balance, payment,
  pricing, auth-cookie or schema changes are included.
- Full-inbox skeletons now match real row geometry: avatar, title, preview,
  timestamp and actions. Browser checks compare the first row's y-position and
  height within 1px rather than just asserting a skeleton exists.
- The header trigger is disabled in server HTML until hydration, using the
  existing client-readiness hook. It no longer accepts clicks that cannot be
  handled yet. Server-render and JavaScript-disabled browser tests cover this.

## Local verification

- Strict build/TypeScript and touched-file ESLint pass. 31 unit/API tests pass:
  14 preview naming/validation/request-lifecycle checks and 17 existing list API
  checks. Stale account responses, sign-out, navigation, closure, malformed data,
  permission loss and timeout recovery are covered.
- 21 inbox/menu browser checks pass at 360, 390, 844×390, 768, 1024, 1280×800,
  1920 and 2560. Both light and dark action states are covered. Tests verify
  skeleton geometry, long text, real inner/page scrolling, visible navigation,
  keyboard focus, Escape, explicit close, retry, empty/permission states and
  horizontal overflow. Layout screenshots were visually reviewed.
- Six shared UI/Pulse/consent/legal regressions and 12 AI-canvas/home/draft
  regressions pass (39 scoped local browser checks). AI responses and messages
  in these suites are intercepted fixtures; no provider charge or customer
  message is generated by them.
- Real signed-in Chrome confirms the local empty preview, explicit close and
  New chat form. No form was submitted. Live real-account acceptance of the
  first candidate confirmed two correctly named conversations and search.
- The first browser run caught a real nested-tooltip/Escape conflict. Removing
  the surrounding Messages tooltip, adding a visible Close button and scoping
  Escape handling resolved it. An intermediate build caught a JSX syntax error;
  corrected before successful build. A retained demo session expired during a
  later run; the public demo login renewed it, then all 20+6 checks passed with
  zero skips/retries. Auth protections were not relaxed.
- Redacted Gitleaks scan of the runtime commit: no leaks.
- The first Live candidate (`c482274`) passed 19/20 menu/inbox checks, but the
  earliest desktop click could precede hydration. A failing SSR test reproduced
  the enabled-before-ready trigger. The readiness fix now passes the unit test
  and the 21 local and Preview browser cases. The first no-JavaScript test also
  incorrectly expected the client-rendered main New chat link; it now verifies
  the actual native sidebar Messages link. The disabled-trigger assertion passes.

## Remaining

Actual new-message delivery/realtime, full mutation-security review, global
conversation search and unread tracking are not validated or implemented by
this slice. Physical mobile keyboards and actual desktop 125% browser zoom
remain manual-device coverage gaps. The full route audit remains active.
The next security slice must test read permission before message writes,
cross-conversation reply references, post-commit realtime failures and private
realtime-channel authorization. These are code-review findings, not a claim
that unauthorized access was attempted against real customer conversations.

The testing and web-design-guidelines skills guided bounded layouts, native
links, accessible controls, truthful states and actual scrolling/focus checks.
